# From external evidence to engineering work

A paper can identify a hypothesis; it cannot declare implementation complete or make an architecture normative.

1. Record the stable source and independent caveats.
2. Ask what architectural or security assumption could be falsified.
3. Compare with existing contracts, implementation, tests and issue ownership.
4. Select `no-action`, `monitor`, `experiment`, `document` or `propose-change`.
5. For change proposals, define observable acceptance and a matched negative/counterfactual case.
6. Validate the owning implementation independently and link exact evidence before calling the proposal integrated.

For authorization-sensitive agent research, keep **memory and agent recommendations separate from current authority**. A verifier proving data lineage is not an authorization decision; a permit being valid is not proof that its intended effect occurred.

See the [Micrantha research prompts](https://github.com/hackelia-micrantha/.github/tree/main/docs/prompts/research) for the controlling workflow.
